# 评测工作流（Eval Bench）

本地工作台「测写」，串联热点检测与选题、案例测试、结果与素材、文章创作。支持连接本机 Agent 执行案例，在写作编辑器中管理正文、媒体及本篇参考资料。

仓库保存应用源码、测试、设计规范和集成服务代码。本地业务数据、文章与运行记录、上传文件、服务凭据、模型与索引、依赖及构建产物不上传；这些内容仍保留在原电脑。写作知识库的部署与连接方式见 [接入说明](docs/writing-knowledge-bridge.md)。

2026-10-29 源码同步与跨电脑接入边界见 [GitHub 交接说明](docs/github-transfer.md)。知识库、索引和模型继续留在原 Mac；网页使用现有文章创作页，四步预览原型未合并。

以下包含首版使用说明和后续功能说明，当前界面规则以 [前端规范](docs/frontend-style-guide.md) 最新章节为准。

把提示词案例、运行配置和生成产物保存到同一条可追溯记录中。本版本提供真实的数据保存和执行回传，默认使用两个明确标注的演示执行器验证流程。真实模型需要配置账号实际可用的接口或本机已有 harness。

## 开始使用

本机已经安装项目依赖后，双击 [启动本地网站.command](/Users/a1234/WorkBuddy/测评网站/启动本地网站.command)，保持终端窗口运行，打开 [本地网站](http://127.0.0.1:43110)。终端中也可以运行 `pnpm dev`。

1. 在案例库选择案例，或通过新建案例录入提示词、输入附件和参考效果。
2. 进入发起测试，选择演示执行器，创建运行。
3. 点击启动演示，或者在项目目录运行网页提供的 `./casebench run <run_id>`。
4. 在矩阵里查看真实落盘并回传的演示产物，填写判定和备注，复制正文、固定链接或下载 ZIP。
5. 在找素材中按判定和执行配置检索过去的正文与备注。

演示输出会保留明显标识，Token 和成本显示未知，不代表真实模型效果。预置案例是可修改的样例，修改会发布新版本。

从其他电脑取得源码时，先安装 Node.js LTS 和 pnpm，再运行：

```sh
pnpm install --frozen-lockfile
pnpm dev
```

## 当前可用功能

- 三个维度的案例筛选、搜索、多选与独立发起页。
- 新建和修改案例；输入附件、参考图与案例版本一起保存。
- 1 至 3 个执行配置的批量运行；并发与超时实际生效。
- 模型和案例的运行快照；每格独立目录；每次重试独立 Attempt。
- 本机执行器登记、运行领取、心跳、重复提交去重和检查点。
- 已落盘产物补传；成功结果不因重复执行命令而重新调用模型。
- 兼容 chat/completions 的接口适配器，以及程序名加参数数组的通用工具适配器。
- 结果矩阵、并排详情、固定 Attempt 链接、用量和错误信息。
- 判定与备注保存、版本冲突检测与修改历史。
- 正文复制、富文本表格复制、常见静态图片复制、单文件与流式 ZIP 下载。
- 文本、图片、单文件网页静态隔离预览与 MP4 播放。

网页中的启动演示按钮仅运行演示配置。已在本机配置的命令行工具可通过运行页的「启动本机执行」按钮启动，使用该工具当前账号和额度；API 配置仍由本机命令明确发起。网页启动前会核对本机配置与运行快照，已完成结果不会再次调用。

### 持久会话与自动发现（2026-10-22）

GPT 持久文本会话现在支持在运行结果页直接追问、停止当前网页轮次、切换产物版本和查看完整对话。首轮评测产物保持不变；追问及失败重试各自归档，并可独立评审。ZIP 导出包含逐轮正文、指标、评审和附件。以上更新取代前面连通性验证记录中关于“尚未验证继续对话、取消”的历史边界。

- 会话栏显示对话轮数、累计执行耗时、输入和输出 Token。执行耗时优先使用原生 Agent 报告的时长，不把两次追问之间的等待计入执行时间。重试消耗计入总量，但不增加对话轮数。
- 用量来自 Agent 报告的累计值差额；缓存输入不会再次叠加。没有报告的值显示“未提供”；仅部分轮次有用量时显示“已知”，不把缺失值当作零。旧任务只有保存了原生会话编号才可恢复；部分历史用量无法补齐。
- 网页会定期同步同一原生会话中的桌面端追问，不覆盖已经归档的首轮产物。桌面端正在执行时，网页暂停发送，避免同时抢占会话。
- 发送有持久请求编号和执行领取锁；网络失败后重试同一条发送不会重复创建模型调用。“恢复本地归档”只补传检查点，不重新推理。失败轮次的“重试这一轮”会产生新调用并保留旧产物。

Agent 配置不再依赖开发电脑的绝对程序路径。启动和刷新连接时，从标准应用安装目录、当前用户目录及 `PATH` 查找支持的 Agent，并读取版本与实际型号。自动发现配置保留稳定 ID，历史测试仍保存当时选定的模型；手写的自定义 harness 继续校验配置哈希。

本轮后续已补齐 WorkBuddy、DeepSeek Harness 和 MiniMax Code，见下一节。GPT 会读取登录状态和动态模型列表，并支持上述持久文本会话；Kimi Code 可检测安装，持续会话仍待适配。发现安装不等于已登录，型号候选不等于账号已获权限。任意厂商的新协议仍需单独适配，不能保证未来版本无需维护。

自定义安装位置可设置 `CASEBENCH_GPT_PROGRAM`、`CASEBENCH_WORKBUDDY_PROGRAM`、`CASEBENCH_DEEPSEEK_PROGRAM`、`CASEBENCH_MINIMAX_PROGRAM`、`CASEBENCH_KIMI_PROGRAM`；设置 `CASEBENCH_DISABLE_DISCOVERY=1` 可关闭自动生成执行配置。会话记录存入原有数据库，追问原始目录位于 `.casebench/conversations/`。目前 GPT 会话适配仍限无附件文本，不自动批准工具操作。

本轮验证通过 21 项后端及端到端测试、15 项组件交互检查和生产构建；端到端测试使用受控模拟 Agent，覆盖首轮、续聊、用量累计、重复请求去重、停止和部分产物保留。另对本机真实 Agent 做了只读探测，以及已有 GPT 会话的关联和同步检查，没有新增真实模型推理。浏览器自动化受当前 Work 设置限制，未进行浏览器截图验收。

### WorkBuddy、DeepSeek Harness 与 MiniMax Code（2026-10-22）

三个 Agent 现已接入同一条网页执行与逐轮归档流程。发起测试时读取执行器实际返回的模型目录，勾选 Agent 后显示具体型号；提交时锁定厂商原始型号编号。网页可查看流式正文、耗时、对话轮数，直接续聊和停止，并保留首轮产物和逐次重试记录。

| Agent | 本机执行入口 | 本次真实验证 |
| --- | --- | --- |
| WorkBuddy | 应用自带 CodeBuddy 的 headless stream-json，使用原会话 resume | 自定义 GLM-5.3 首轮、同会话追问成功；内置 auto 仍返回执行器未授权 |

| MiniMax Code | 项目内官方 `@minimax-ai/code` 0.6.12 的 ACP 接口 | 已配置的自定义 M3.1-Flash 首轮、同会话追问成功；托管型号返回余额不足，旧自定义 M2.7 已被服务商停用 |

WorkBuddy 和 DeepSeek 无需另装 CLI。MiniMax 桌面应用没有独立的公开 CLI 入口，因此在 `tools/minimax-cli/` 安装了官方 CLI；不改变系统全局命令，使用现有 `~/.minimax` 配置。换电脑需自行登录或配置服务商账号，并在项目中安装这个依赖：

```sh

```

执行器来自 `PATH`、标准安装位置、用户安装目录或上面的路径覆盖变量；MiniMax 另有项目内依赖回退。模型目录动态读取，不写死在网页。刷新连接不产生模型推理；目录中出现某个型号不表示账号有足够额度或已获服务商权限。页面会显示已知失败提示，并优先推荐最近真实跑通的型号；历史错误不会永久禁止已重新授权的账号重试。

WorkBuddy 的用量返回会话累计值，续聊时扣除上一轮累计量。MiniMax 只有明确声明支持本地 `/usage` 命令时，才读取执行前后的会话统计并计算差额；这不会触发额外模型推理或增加对话轮数。缓存 Token 属于输入 Token 的子集，不重复相加。DeepSeek 当前 ACP 未提供输入、输出明细，显示“未提供”，不把上下文占用数当成生成用量。旧任务缺少基线时也不会伪造逐轮 Token。

这三个新适配目前支持无附件文本评测，工具操作不自动授权。它们建立的是各自执行器的持久本机会话；**尚未验证会话会自动出现在相应桌面应用的任务列表，也未接入桌面端反向对话同步**。已验证的是网页发起、网页进度与网页续聊。WorkBuddy 当前生产安装包将本机评测接口固定关闭，重启不能单独启用，因此本次没有为此重启或修改安装包。

本轮通过 25 项后端测试、16 项组件交互检查与生产构建。自动化端到端用受控 Agent 验证 HTTP → 独立 Runner → 原生协议；上述两组成功记录和账户失败另有真实本机调用证据。验收说明见 [本轮记录](output/three-agents-20261022/README.md)。

## 数据存在哪里

网站当前仅监听 `127.0.0.1`，数据保存在项目的 `.casebench/`：

```text
.casebench/
  postgres/                 本地 PGlite PostgreSQL 数据
  files/<file_id>            上传与归档文件，按不可复用 ID 保存
  device-<server_hash>.json  本机执行器凭据，文件权限为 0600
  runs/<run_id>/<result_id>/<attempt_id>/
    inputs/                 校验后的输入附件
    out/                    这次尝试的产物
    checkpoint.json         完成状态、哈希与待补传清单
  logs/<run_id>.log          网页演示启动的执行日志
  config.json               本机执行配置，不存密钥值
```

`.casebench/` 已被 Git 忽略。备份开发数据需要在停止服务后同时备份数据库目录和 files 目录；本地运行目录是执行者保留的原始副本。

为便于先开发，本版本使用可持久化的嵌入式 PostgreSQL，不依赖另装数据库服务。设置专用环境变量 `CASEBENCH_DATABASE_URL` 后可切换到独立 PostgreSQL，仍使用同一套 Drizzle 表定义和查询。该连接应指向为本项目专门创建的空数据库。文件存储目前是本地实现，私有对象存储适配将随部署接入。

## 接入真实模型与 harness

复制 [config.example.json](/Users/a1234/WorkBuddy/测评网站/config.example.json) 到 `.casebench/config.json`，保留需要的配置，并把占位值换成实际信息。配置中的 `id` 必须唯一，网站用它与本机执行器匹配；运行会锁定配置哈希。

兼容接口配置的 `baseUrl` 为 `/chat/completions` 前的基础地址，型号使用账号实际可用的标识。`apiKeyEnv` 填本机环境变量的名称，密钥值只在本机设置。首版不把不同服务商的思考参数强行映射为统一档位，必要参数放在经过验证的 `requestParams` 中。

通用工具配置中的 `program` 为已安装可执行程序，`args` 根据该工具的实际用法填写。示例参数并非任何厂商的通用参数，需要按现有 harness 调整。支持这些占位符：

| 占位符 | 内容 |
| --- | --- |
| `{{promptFile}}` | 含提示词及执行要求的文本文件 |
| `{{taskFile}}` | 含案例、模型、输入附件路径和输出目录的 JSON 文件 |
| `{{workspace}}` | 本次 Attempt 的独立工作目录 |
| `{{outputDir}}` | 需要写入产物的目录 |
| `{{model}}` | 锁定的实际型号标识 |

工具也能读取 `CASEBENCH_TASK_FILE` 和 `CASEBENCH_OUTPUT_DIR` 环境变量。执行器不使用 shell 拼接命令，输入文件校验后下载到本次目录，收集产物时拒绝符号链接和越界路径。具体工具仍应启用其自身的工作目录权限控制。

```sh
./casebench doctor
./casebench login
./casebench run <run_id>
./casebench sync <run_id>
./casebench resume <run_id>
```

`doctor` 检查程序是否存在及凭据环境变量是否已设置，不会偷偷发模型请求验证权限。接口账号权限和工具登录状态在实际执行时核实。

网络失败后，`sync` 只补传已完成的本地产物。上次已开始但不能确认是否结束的任务不会自动重复调用；明确需要重新尝试时使用 `./casebench resume <run_id> --retry-failed`，这可能产生新费用。成功任务始终跳过。运行绑定到最初接入的设备，首版不自动换电脑接管。

## 当前边界

这是本机开发版本，尚未接入团队登录、云端对象存储及公网部署。网页请求限制本机地址和来源，执行器持有独立设备凭据。将来部署团队服务器前需要完成正式身份和权限接入。

每文件上限 25 MB，每格合计 100 MB、最多 30 个文件。网页预览支持自包含 HTML 的静态显示，不执行生成的脚本，限制外部资源与弹窗；多文件应用可以打包下载，资源映射与独立预览源仍需完善。API 适配器目前支持文本、常见图片输入和文本附件；其他 API 协议、厂商专用 harness 日志及用量需要逐个适配。

完整 GIF 剪辑、FFmpeg 九宫格、Excel/ZIP 案例批量导入、外部只读分享、讨论与 @ 人、完整尝试历史列表仍待开发。真实模型未配置时，不把演示执行成功当作厂商兼容性验证。
