# 资讯叙事蓝图试点设计（用户已批准并实施）

## 意图与已知约束

用户要“怎样叙事、素材放在哪里”，已验证当前模板和调用链不满足，现指定第一批为资讯类。沿用 Figma 的选题与写作流程、Obsidian 实时知识库、Haystack/FastEmbed 本地检索与 DeepSeek。素材不足不能先把依赖它的判断写完。推荐和起草各一次模型调用，Humanizer-zh 在同次起草/改稿中使用。暂不做服务器部署或其他体裁改造。

这是资讯试点，用户已通过“按方案实施”批准；新增数据与接入行为已实施。`docs/news-narrative-pilot.md` 是已读五篇原文后的可审阅打样；原文段号和媒体节点只作为叙事证据，历史事实不移入新热点。

## Approaches

推荐“新增叙事蓝图层＋修正推荐/起草链路”：复用原文、旧分析和 27 个家族，先用五张蓝图跑通。仅调整提示词缺少稳定素材位置依据；直接重拆全部文章会在新标准尚未成稿验证时扩大返工。上述路线已向用户说明，用户指定资讯优先；本文件的具体工程设计已获用户批准。

## 本轮交付与范围

1. 五张资讯蓝图：NEWS-CHOICE / UPDATE / PRESSURE / DEMO / DISPUTE，来源及逐节点说明在打样文件中。
2. Obsidian 新增 `叙事蓝图/资讯/`，不覆盖原文、旧拆解和旧结构。单独使用 `类型: 叙事蓝图`、稳定 `蓝图ID`、`体裁: 资讯`、`关联结构: N1..N4`、`蓝图版本`、`状态: 试用`；引用来源 ID/段号及内容摘要。
3. 实时加载、检索、方向卡、起草、常规改稿支持蓝图和材料依赖。仍由用户确认方向才开始起草。
4. 功能与坏样例验收，保留用户正常试稿的质量验收入口。其他体裁保持现有流程；不声称已修好全库。

写新蓝图文件只在确认后的实施阶段进行；现有原文和旧分析继续只读。路径不能使用 `全文拆解v6`：加载器采用最高累计版本，少量新样本会错误取代已有千篇分析的活动版本。

## 知识来源与数据表示

蓝图是现有 Vault 的新类型。按同一只读扫描规则更新；增加 typed `blueprints` 列表，不能让蓝图被当成原文或重复的普通笔记。`articles`、原有已拆解数及 27 个结构的统计不因此增减，单列可用蓝图数。

每张蓝图记录适用目的、材料前提、边界、原文观察与可复用建议。每个节点记录：

- 稳定节点 ID、读者此时的问题、叙事动作、进入下个节点的理由。
- 有序 beats，类型为 `narration / material / observation / transition`，不能只存章节名和独立材料清单。
- material 的 ID、种类、叙事作用、材料前/后要做什么、必需/可选，以及历史原文锚点。材料种类支持事实、引文、数值对照、文字案例、图片与视频。
- observation 对 material IDs 的依赖。没有材料时不能输出已经证实的观察与结论。
- 原文依据与当前新稿事实来源分开。没有完整媒体原件时只确认媒体节点次序，不声称看过画面。

Markdown 正文使用便于人在 Obsidian 编辑的固定小节与编号字段，避免将大量 JSON 放到用户可读正文。字段 schema 和校验错误明细交给实现者确定；必须有测试夹具及清晰错误提示。

已恢复的五篇原始 Markdown 作为一次性校准依据，生产调用仍只认 Vault。部分缺失的媒体位置写在新蓝图来源锚点里；不要求网站永久读取原始导入 JSON 或私有临时目录。

## 检索与推荐

文章检索继续负责找主题/写法证据；蓝图检索另按写作任务、材料前提及叙事路径排序。新增蓝图的向量片段按增量索引接入，不能为了五张蓝图全量重算原有向量或修改模型。

可以将蓝图作为新 `kind=blueprint`，也可复用现有索引存储加类型标识；这是实现者的选择，但 Python 允许类型、Node 源映射、RRF 去重与元数据校验必须一致。蓝图详情从当前完整记录加载，不能用局部相似片段代替整张蓝图。

资讯 `/api/recommend` 的同一次 DeepSeek 调用，返回三个方向，各含角度、所选蓝图 ID/版本、原 N 家族、实例依据，以及适配本次选题的有序叙事计划。三条可以采用同一蓝图的不同有效变体，不强行挑三种不适合的蓝图凑数；要求角度、切入或推进方式有实质差别。材料不足以支持三个可直接成稿的方案时明确显示缺口，不能伪装材料齐备。

每个动态 material 关联本次 `references` 的 ID 或 `missing`。仅有 URL 不代表内容已读；历史案例也不能充当新稿事实材料。媒体链接/文字描述不能自动视为已看过媒体。程序可验证 ID、正文存在与声明一致性，材料是否足以支持结论仍需要作者审阅。

优先给模型少量完整蓝图和相关例证，控制输入长度；不能把所有历史文章全文装进请求。保存推荐签名时纳入 schema、蓝图内容摘要、顺序、材料绑定和知识库版本。

## 页面呈现

保持现有方向卡外观与确认流程。在卡内把原来的纯箭头提纲扩展成有序叙事节点，显示“此处做什么→用什么材料→之后怎样承接”。材料就近标明“已有资料 / 待补”，展开可看为什么放在此处及原文段号。无需新建顶级页面，也不另弹一个必须审批的材料流程。

缺材料的方向仍可选择并生成带待填部分的初稿，不能称为完整可发布成稿。素材位置可在开场、段中、段间、局部判断后或结尾，由该节点作用决定。

## 起草与校验

资讯使用有版本的内部输出协议，其他体裁保留旧协议。推荐得到的计划由服务端冻结，起草前计算可写 beat IDs。写作模型在原有一次请求内输出 `title / structureId / sourceIds / blocks[{beatId, markdown}]`，允许键、顺序与必填条件要严格校验。

服务端根据冻结计划拼装 Markdown：

- 已有材料的可写 beats 正常生成，只引用本次资料。
- 缺失 material beats 在规定位置插入具体素材位。
- 依赖缺料的 observation beats 插入具体待写说明，不让模型抢先给出测试胜负等结论；缺料不阻止写其他有依据的部分。
- 未知 beat、重复 beat、越过材料依赖、所选蓝图与结构不一致或来源越界时拒绝，不在后台自动多发一次“修稿”调用。
- 材料全部齐备时允许没有素材位，不能继续强制每篇必须出现一次“素材位”。

公开响应继续包含 `title / markdown / structureId / sourceIds / materialSlots:string[]` 供现有预览/导出使用，资讯额外保存版本化计划、block 映射及正文指纹。API 依据新内部结构校验，不能只靠 Markdown 是否包含“素材位”。正文事实与文学质量无法由这些结构校验完全证明。

## 修改、兼容与失效

未手动编辑的资讯稿在同一次改稿调用中沿用计划与 blocks；仅调整文案时保持材料 ID、位置和依赖。要求改讲法时重新匹配方向，沿用当前产品已有路径。

用户自由编辑 Markdown 后，若内容指纹与最后机器渲染稿不一致，保留其所有文字，不伪称原有 block 映射仍精确。普通改稿仍可执行一次，携带当前正文与蓝图作为约束，返回针对原正文的局部段落修改，由服务端应用，未触及的文字原样保留；跨段整篇替换、未知/歧义/重叠修改均拒绝。标记结构位置尚待作者核对；不得静默丢掉用户文字以恢复机器计划，也不自动追加另一轮模型调用。重新获取方向并生成可以恢复严格的 block 校验。该边界应显示为简短状态，不暴露内部 schema。

旧会话、已保存草稿与导出继续可读；旧资讯推荐不自动补蓝图，开始新的起草需重新匹配。蓝图新增/编辑/删除会更新知识版本并使过期推荐失效。无蓝图或损坏时资讯推荐明确提示，没有默认蓝图替代或静态包回退；已有旧稿仍可查看/编辑。

## 验证与费用

自动验证：真实临时 Vault 的蓝图更新/删除、材料位顺序、依赖缺料时观察待填、全材料齐备无占位、未知来源、重复/未知 beat、推荐过期、旧稿兼容、自由编辑不丢字、单次调用，以及现有两个尾部挂素材坏样例在严格新协议下被拒绝。

数据验证：五张卡的段号、原文顺序、媒体节点、归属与限制可追溯；当前旧标签错误不作为新观察的锚点。

质量验证：建议用户正常使用网页，对两组未参与五张卡归纳的选题与材料试稿，检查叙事路径、素材是否推进、缺料判断是否留空。这里的“新”指未参与校准，不要求是今日新闻；历史事件必须标明日期。用户启动的推荐/起草使用正常 DeepSeek 调用。本轮实施验收不通过脚本自动消费真实 DeepSeek API，也不自动批量调用、重试、评审或润色。若用户另行要求同题新旧成稿对照，再明确范围并记录实际次数/用量。模拟接口只证明接线和校验，不冒充生成质量证据。

验收通过后才扩大样本与其他体裁；不按处理篇数自动宣布叙事成熟。CPU/内存和首轮/热查询延迟继续单独记录，不把向量分数当质量评分。

## 留给实现者的常规选择

小节的具体解析规则、JSON Schema 库或手写校验、SQLite 新类型表达、细微排版与错误码命名由实现者选择，遵循已有依赖和 Figma，不引入新的服务或额外生成调用。设计中的数据不确定性须保留，不靠实现时猜测补出原文未出现的转折或素材。

## 设计检查

五篇与原始导入快照的清洗后段落逐一一致，22 组段号锚点及两处明确媒体顺序断言通过，证据见 `docs/qa/news-narrative-pilot-evidence.json`。一名独立 gpt-6-luna 审阅者按 builder-check 提示审阅本设计及打样文档，未提出阻碍制定计划的问题（`nothing important left`）。这项检查不是用户批准、实现通过或写作质量证明。
