# 叙事结构与素材落位：五篇原文验证

2026-10-27。范围为五篇定向样本，不是全库质量抽样。本轮没有修改 Vault、结构卡或网页生成规则，没有调用付费 DeepSeek。

## 结论

用户指出的问题成立：当前表示把很多“素材推动叙事”的关系压成了内容标题和材料清单；网页调用又缺少专门承载阶段细节、素材落位与钩子承接的字段。现有校验允许大段先写判断、末尾再挂缺失证据的稿件通过。

同时修正上一轮示例的适用边界：“素材先出、再判断”只适用于部分单元。教程可在短操作/短判断之后跟截图，故事可以在结尾放歌曲完成回扣。正确目标是材料有叙事作用且与前后文相连，不能统一改成段首，也不能禁止所有段尾材料。

## 验证方法与证据

1. 读五篇当前原文转写及 v5 拆解，按段号核对叙事顺序。
2. 找回四篇在原始导入快照 `../work/final_articles.json` 中保留的 Markdown 正文。它们的清洗后段落与当前 Vault 逐段比较，忽略空白后全部一致，确认不是拿其他版本文章比较。
3. 对照原始 Markdown 媒体节点前后文本，执行 10 条明确的位置断言。四篇原始 Markdown 中分别有 14、21、24、47 个图片引用（含封面、装饰及视频封面，不能当作有效案例数）；对应 Vault 正文的 Markdown 图片引用均为 0。文字中仍保留部分视频播放标签和图片描述。
4. 运行真实 Vault 读取、实际 Haystack/FastEmbed 检索及当前 API，截获模型请求；以本地模拟生成接口回复，未访问 DeepSeek。分别验证测评、评论的推荐与成文，共截获 4 次请求。
5. 模拟接口故意返回“无实测材料却写好判断、把素材位放到最后”的坏稿，检查现有后端会不会拒绝。

证据：`docs/qa/narrative-media-order.json`、`docs/qa/narrative-contract-live.json`。完整截获提示词保存在忽略目录 `.rag-cache/narrative-validation/provider-payloads.json`，未保存凭证。可复跑脚本：`scripts/qa-narrative-media.py`、`scripts/qa-narrative-contract.mjs`。

媒体断言证明节点的位置，**没有观看或核验图片/视频的实际内容**；第五篇 APPSO 原文仅检查当前文字、图片说明与案例顺序。文中的第三方事件、技术能力和人物经历只是原文叙事证据，未在本轮做外部事实核查。

## 以 R2 为例，合格抽象应细到哪里

| 叙事单元 | 读者此时要知道什么 | 应安排的材料及位置 | 材料后的动作 |
| --- | --- | --- | --- |
| 建立选择问题 | 这些方案究竟怎样选？ | 已掌握的真实需求、比较范围；放在测试前交代 | 给出本轮可比较的条件，不能暗示未测过的对象已测完 |
| 第一轮任务 | 这一项为什么容易出问题？ | 短解释后放相同输入和各方案输出 | 根据刚展示的结果比较具体差异；没输出时不预写胜负 |
| 换场景 | 上一轮结论在另一种使用条件下还成立吗？ | 新任务的输入/输出与必要反例 | 说明结论是否延续或反转，带出更细的适用范围 |
| 交还选择 | 我自己的工作该选哪个？ | 汇集前几轮已有证据，缺成本记录时明确留空 | 给按场景区分的选择建议，不补造总冠军 |

## 后端实际请求验证

- 五篇当前加载记录的 `stageNotes`、`hookChains` 均为空；开头说明有内容，但它没有作为专门字段交给模型。
- 两次推荐各发送 12 篇真实检索案例，阶段标题可以到达模型；阶段细节、钩子链与专门的开头/中段/结尾字段都未发送。
- 两次成文分别带入 5 篇、2 篇案例，仍缺少这些专门字段。局部 `analysisExcerpt` / `historicalArticleExcerpt` **可能仍含一部分细节**，因此不能声称模型完全看不到任何叙事证据；问题是细节不完整、不可稳定落位。
- 两次模拟坏稿都被当前 API 以 HTTP 200 接受。证明当前校验不会拒绝这种叙事/素材脱节；没有证明真实 DeepSeek 会以多大概率生成它，也没有完成新旧生成效果对照。
- 1,000 篇中包含“推进关系：按原文顺序推进”的篇数重新核对为 836，共 7,140 次。这是表述计数，不能直接当作 836 篇不合格的判定。

## 对上一轮判断的修正

**已证实：** 抽象缺少稳定落位表示、适配层压缩细节、验收放行坏样例、媒体位置在转写时丢失。

**新增发现：** 四篇的媒体节点还保存在原始导入快照，可以在这些已验证来源上补回位置，不必立即重新抓取或全量付费重拆。

**仍待验证：** 采用新结构数据后，真实 DeepSeek 的三个方向和成稿是否明显改善，以及其他体裁/更多样本是否适用。这需要后续校准与生成对照；本轮不把“诊断成立”写成“写作问题已经修好”。
