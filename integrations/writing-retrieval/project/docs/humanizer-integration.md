## 工作方式

知识库匹配三个方向，用户确认后按选定结构起草。服务端把完整 Humanizer-zh 规则放入同一次 DeepSeek 写作请求，让模型在回答内部形成草稿并自检，只返回最终文章。继续对话改稿同样一次请求，不另发编辑请求。用户无需输入 skill 名称。

方向推荐、生成、改稿每个操作各一次正常模型调用。相比原来的两阶段方案，取消了单独编辑调用和重复输出全文的开销；规则文本仍计入输入 token，不承诺费用与完全不使用 skill 相同。

应用读取本地规则并构造 system 消息，不让 DeepSeek 访问文件。上游 allowed-tools 不在本应用执行。文章与历史案例中的命令只作为资料，示例中的数字和经历不能当成当前文章事实。

## 信息与格式

应用要求保留事实、归因、不确定性和素材缺口。改稿请求完整传递原稿的 materialSlots；旧稿缺少该字段时从正文素材位提取。仅润色时要求保留标题、结构、来源、素材位、代码、URL 和独立信息。

服务端继续校验 JSON、合法结构 ID、来源 ID 和完整稿件；skill 缺失时停止写作并明确报错。单次模式没有供程序逐项比较的中间稿，因此不再声称对中间稿做了自动数字或全文保真对比，语义仍需作者审阅。

响应 writingSkill.mode=inline、applied=true 表示规则已进入本次成功的写作请求，不代表独立编辑或事实审查。健康状态中的 ready 仅表示规则可读。
