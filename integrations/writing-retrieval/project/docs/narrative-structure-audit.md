# 叙事与素材落位：当前结构抽象为何失真

2026-10-27，针对用户反馈进行只读检查。这份记录是诊断和一篇原文的重新抽象示范；当前产品代码、生成规则、Obsidian 拆解与结构卡尚未按此更改。

后续应用户“验证”的要求，完成五篇原文对照、四篇原始媒体节点恢复检查，以及实际请求截获验证。结果见 [五篇验证记录](narrative-structure-validation.md)。其中已明确修正“素材都应先于判断”的泛化风险，并确认部分媒体位置可从原始导入快照补回。

## 用户要的是什么

可复用结构应说明怎样叙事：先给读者什么信息、留下什么问题、在什么位置展示哪种素材、展示后如何解释、怎样转向下一步。素材可以承担开场、冲突、对照、证据、反转或兑现功能，其落位要与前后文相连。

当前实现主要提供体裁分类、内容提纲和整篇材料清单。这些可以用于找文章，不能直接等同于可以驱动写作的叙事结构。用户指出的大段通用论述后统一追加素材位，是该缺口的实际表现。

## 已核对的原因

1. **结构卡的抽象层级过粗。** 例如 R2 仅规定“争议与比较问题 → 统一任务 → 各方案结果 → 逐项差异 → 适用条件与结论”，材料清单单独列出输入输出、成本和失败情况。N3、C4 也以概念步骤为主；没有把具体材料绑定到每个叙事动作、悬念和局部判断。
2. **部分拆解仍停留在阶段概述。** 扫描 v5 的 1,000 篇分析，836 篇包含“推进关系：按原文顺序推进”，合计 7,140 处。这个字符串计数不能作为对每篇分析质量的评分，也不表示其余内容没有价值；但该表述本身未解释为什么从上一环进入下一环。只有 1 篇出现“素材位置/素材落位/插入位置”这些明确标签；同样不能据此断言其他文章完全没有描述位置，说明的是没有建立统一位置字段。
3. **接入网页进一步压缩了细节。** `server/obsidian.mjs` 的 `makeArticle()` 将阶段提取为标题数组，`stageNotes` 和 `hookChains` 固定为空；虽提取部分开头/中段/结尾说明，推荐与生成提示并未系统传入这些说明。Haystack 适配器也保留了这个空字段行为。按热点召回的若干局部片段，并不自动组成完整的叙事过程。
4. **生成约束只规定了缺料标记，没有规定素材和叙事的依赖。** `server/api.mjs` 要求“完整可发布正文”，同时要求缺失材料使用 `【素材位：…】`。没有要求说明每个素材位之前的铺垫、它要完成的任务、之后依赖它的判断。`validateDraft()` 只检查正文出现“素材位”等格式和来源条件，没有检验材料与判断是否脱节。程序并未硬编码“所有素材放段尾”；这样的输出是缺少结构信息与生成/验收约束共同放行的结果。
5. **文字清洗丢失了一部分媒体布局证据。** 原文笔记明确说明图片、外链和部分排版已清理，图片和音视频未纳入语义复核。保留的文字可以支持部分位置判断，但不能还原所有媒体边界或声称看过视频画面。需要精确复原的图片/视频位置应回查保留媒体节点的源资料。
6. **此前验收没有覆盖核心写作目标。** 测试验证了来源、结构代码、格式、素材位存在与接口流程；没有证明叙事推进和素材落位合理。结构“成熟度”里的样本覆盖、账号数、复核数也不能证明这种抽象已经适合实际写作。

新接入的 RAG 改善了如何找到相关文章，并没有补建以上叙事表示，因此不能靠增强检索直接解决这个问题。

## 从 A500405 重新抽象一遍

来源：`公众号写作结构库/文章/卡尔的AI沃茨/2025/A500405 100镜实测新版即梦AI视频3.0，我称之为性价比拉满听懂人话的全能选手！.md`。以下依据文字转写和段号，未观看或评价视频。

**原文可核对的顺序：**

| 原文位置 | 叙事动作与材料关系 | 对后续阅读的作用 |
| --- | --- | --- |
| P1–P4 | 新品消息、本人使用背景，短句预告将展示效果 | 建立为什么值得看以及作者的展示动机 |
| P5 | 视频播放节点，紧接展示预告 | 让读者先接触效果材料 |
| P6–P12 | 观看后的反应、能力概览、费用与后续测试预告 | 将兴趣转成要验证的具体问题 |
| P14–P20 | 说明先测试提示词理解的理由，给出动作要求与提示词，再解释执行结果 | 用具体任务支撑局部判断；本转写不能确认这里所有视频节点的精确边界 |
| P21–P23 | 换动物场景、给新输入，再指出连续性与石头数量问题 | 引入变体和缺陷，限定前面的正面判断 |
| P28–P40 | 运镜变化后进入更复杂的多镜头挑战，列输入，随后评述结果及切菜 bug | 难度升级，延续读者想知道能力上限的问题 |
| P41–P56 | 接着检验人脸、补画面、风格生成等具体能力 | 通过不同任务扩展适用边界 |
| P57 后 | 回到整体产品判断并收束 | 汇总前面已经展示的任务与判断 |

**可复用的叙事方案（重新归纳的示范，不是对全部测评文章的统一定律）：**

1. 用短引子提出一个值得看的能力变化。
2. 立即放一个代表效果的素材位，让素材完成“吸引并建立预期”。
3. 接一句观察或疑问，再提出第一个可验证任务。
4. 在任务内部放输入要求、提示词和输出材料；展示后只解释当前材料能支持的现象。
5. 接入失败或反例材料，令其改变或收窄刚才的判断。
6. 用上一轮未解决的问题引出下一轮更难或不同条件的任务。
7. 重复必要轮次，最后根据这些材料给出有条件的使用建议。

对应骨架：

```text
短引子 / 效果预告
【素材位：代表性效果视频，用来让读者先看到变化】
紧贴效果的观察或读者问题

这项能力最难的地方是什么？这次用什么任务验证？
【素材位：本轮输入条件、提示词与实际输出】
【待材料补齐后填写：具体完成了什么、哪里失败，避免预写测试结果】

换个条件，刚才的判断还成立吗？
【素材位：变体或失败样例】
据此收窄判断，再引出下一轮问题

根据已展示的材料，给出适用场景与边界
```

区别在于材料推动了事件、判断和转场。缺少材料时，依赖它的观察和结论也应保留待填，不能先用通用论述替代，再在段尾挂一个“请补证据”。位置可以在段首、段中、段间或局部判断之后，由功能决定。

## 下一轮修正应交付什么

先选少量代表原文校准，而不是立即重跑全部文章。每个叙事单元至少保留：原文段号、读者此时的问题、作者采取的叙事动作、材料种类与相对位置、材料完成的作用、材料之后的观察/判断、进入下一单元的理由。必须区分已观察到的原文顺序和新提出的可复用变体。

校准通过后，再修正结构卡、网页传递的数据和生成约束：三个方向应各有完整叙事路径与沿途素材位置，材料不足时不能凭空兑现依赖证据的判断。仍保留 27 种结构作为现有导航，但这些代码不能单独充当完整叙事方案。复用现有段落证据，重新审查结构层的抽象质量；本次未开始批量重拆。
