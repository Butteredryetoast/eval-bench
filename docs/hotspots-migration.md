- 恢复快照为 6,103 个事件、6,685 条来源记录、57 个搜集案例（12 已入库）、44 个已接入信源、2 个实际附件、0 个人工实测。候选目录另有种子及观测条目，运行时合计 435 个候选，不等于 435 个已启用信源。
- `.data/postgres` 是热点独立数据；`.casebench` 仍是原站数据。`.data/monitor-assets` 为原始附件；加入素材后另有原站文件记录，重复操作去重。
- 原始 dump 只作首次恢复，普通启动绝不重放。原 dump 的 `pool_search.body` 使用 lz4 列压缩；本机编译的 PostgreSQL 未启用 lz4，因此恢复 SQL 仅把该列的存储策略改成 pglz，业务行与 ID 不变。
- 原包未含实际服务密钥。自动模型处理已关闭，定时信源采集未启用；页面可手动同步，模型评分／翻译需先保存密钥和明确启用调用。自动模型处理还需另行在预算页选择范围；只处理启用之后的新鲜资料，不重跑历史全量。
- 后台只消费采集和热点队列，不启动原站新闻发布、日报生成、通知任务。未完成历史任务不会在迁移后自动重跑；本包待处理任务为 0。
- 公众号及 X API、公开网页抓取、视频下载取决于实际凭据、余额、来源可访问性和防抓取规则；本次未用虚假密钥做外部付费验收。浏览器采集扩展已适配主站端口，需用户在 Chrome 加载解压扩展后才能采集外部网页。

## 启停与备份

主站启动器 `scripts/dev.mjs` 在真实工作区启动时会检查并拉起热点服务；指定 `CASEBENCH_DATA_DIR` 的验收启动器不会触碰真实热点进程。

```sh
node scripts/hotspots.mjs start
node scripts/hotspots.mjs status
node scripts/hotspots.mjs stop
```

`stop` 只停热点 API 与队列消费，主站和数据库继续运行。数据库需停时使用该独立目录的 `pg_ctl`，不能关闭机器上其他 PostgreSQL 实例。数据库、内部桥接凭据位于 `.data/database.json`、`bridge.json`，权限 600，不得上传公共仓库。模型与采集服务密钥在 `.data/credentials` 中，不向前端回显。

迁移前原站完整备份在 `output/hotspots-migration-20261027/before.tar.gz`；原始 ZIP 与 dump 保留。验收报告、原站前后快照、数据库恢复日志和截图在同目录。日常备份需同时保存 `.casebench`、热点数据库 dump 和 monitor-assets；不能只复制网页代码。迁往 Linux 服务器时使用该平台的 PostgreSQL，不能复制本机 macOS 二进制运行。
