## 在接收电脑启动网站

使用 Node.js 和 `package.json` 指定版本的 pnpm：

```sh
git clone https://github.com/Butteredryetoast/eval-bench.git
cd eval-bench
pnpm install --frozen-lockfile
pnpm dev
```

默认入口为 <http://127.0.0.1:43110>。这是源码启动；不会出现原 Mac 的文章、测试记录或热点数据库。生产构建可运行 `pnpm build`，之后用 `pnpm start` 启动。

GPT/Codex、WorkBuddy 的程序与登录状态属于运行网站的机器。执行器源码已保留，但新机器需安装、登录对应工具或配置已授权的 API；仅连接知识库不会自动取得原 Mac 的模型执行能力。当前原 Mac 的模型入口见 [本机模型说明](local-model-agents.md)。

热点模块依赖独立 PostgreSQL、后台服务及私有桥接配置，不能把根目录 `pnpm dev` 当成其初始化流程。原迁移记录见 [热点迁移说明](hotspots-migration.md)，原 `.data` 中的 macOS 数据库程序不能直接搬到 Linux。

## 网站继续访问原 Mac 知识库

1. 原 Mac 保持开机、联网，并运行现有 `127.0.0.1:43130` 检索桥接。
2. 新电脑与原 Mac 之间配置受控私有网络或隧道，使新电脑的网站后端能访问桥接的 `/health` 和 `/context`。
3. 在网站的写作设置里填入网站后端实际可达的服务根地址与桥接访问令牌，启用知识库并检查连接。令牌通过私下渠道配置，不提交 Git。
4. 连接成功后再验证一个真实选题：生成前检索与读取知识库，结果保留实际引用，全文按素材依赖保留缺口。

新电脑直接填写 `127.0.0.1:43130` 会访问新电脑自身；只有已把隧道映射到该端口时才适用。前端页面与 GitHub 仓库都不保存原 Mac 的私有访问令牌。

本次只同步源码，没有配置跨电脑隧道、部署线上网站或完成跨机器连通验收。现有本机服务状态与维护命令见 [本机知识库说明](local-writing-knowledge.md)。
