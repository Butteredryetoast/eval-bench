# 必查知识库与可追溯引用

用户要求结构、大纲和正文生成前必查 Obsidian；未拆解但有正文的文章也可引用；生成后附上引用对象。沿用本机检索、原生模型、单次写作与现有前端。

采用后端强制检索、读入正文、结构化引用与服务端附录。只加提示词无法保证执行；把所有检索命中都列作实际引用会误导，因此均不采用。知识库关闭、不可用或没有可读来源时暂停模型调用；不自动重试模型。

1. 桥接返回当前检索文章及蓝图来源文章的安全元数据和有界正文，标明全文或截取。候选正文不因未拆解而排除。先测候选全文和蓝图父文章，再实现。
2. 写作请求强制先得到可读知识库上下文。模型在原有 JSON 中返回引用 ID、用途、位置和对应原文短引文。后端校验这些引用确实来自本轮可读内容；实际蓝图与正文素材涉及的文章不能漏列。未核实的旧报道保留日期和归属，不改写成当前事实。
3. 服务端在讨论/方向回复和全文末尾附引用列表，选区修改只在助手消息中附列表，保留精确替换范围。保存来源快照元数据用于追溯，不复制全文到稿件历史。
4. 用隔离夹具验证无知识库零模型调用、先检索后生成、未拆解正文可引用、伪造引用拒绝、引用列表和选区保护。运行完整测试、类型检查，重启本项目桥接并用真实库与一次原生生成验收。

正文有长度预算，传入模型的长文截取会明确记录范围；不声称读过未传入的部分。原始 Vault、索引、模型、前端设计及用户已有文章保持原状。
